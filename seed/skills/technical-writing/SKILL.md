# Technical writing

1. Identify the reader, goal, prerequisites and source of truth in the implementation.
2. Lead with the behavior or outcome. Use plain language and concrete examples.
3. Keep commands copyable and label placeholders. Include required permissions and expected results only where relevant.
4. Separate configuration examples from actual production settings. Never copy API keys, tokens or private data into documentation.
5. Explain meaningful limitations and recovery steps. Cross-check names, paths and links against source files.
6. Verify document structure and any local examples that can safely be executed.

Deliver: the requested document with consistent terminology and a brief validation note. Do not claim deployment or external verification without doing it.
